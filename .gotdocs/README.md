# `.gotdocs/`

Control directory for **gotdocs**: docs, runbooks, onboarding and dependency notes live in the
repo next to the code they describe, and a vendored CLI plus git hooks refuse to let a doc go
stale when the code it `covers` changes.

Nothing in here is a document. The documents live in the configured roots — `docs/`,
`runbooks/`, `onboarding/`, `dependencies/`, `decisions/`. This directory holds the config,
the schema, the templates, the generated index and the generated doc-debt ledger.

## What every file here is

| Path | Generated? | Edit by hand? | What it is |
| --- | --- | --- | --- |
| `config.json` | no | yes | The gotdocs config: doc roots, enforcement levels, ignore globs, skip token, plus the `debt` and `publish` blocks. See below. |
| `schema.json` | no | yes | JSON Schema (draft 2020-12) for the frontmatter object. Documentation and editor integration only — see "Why the schema is not enforced". |
| `index.json` | **yes** | **no** | Machine index of every doc: id, path, title, type, summary, covers, tags, owners, status, updated, verified_at. Sorted by `id`. This is what `gotdocs check` reads to decide what a code change impacts. |
| `INDEX.md` | **yes** | **no** | Token-cheap human/agent index. One line per doc, grouped by type. The file an agent reads first, before opening any doc. |
| `debt.jsonl` | **yes** | **no** | The doc-debt ledger: one JSON object per line, one line per finding that was accepted instead of fixed. Written by `gotdocs debt record`. See [docs/doc-debt.md](../docs/doc-debt.md). |
| `DEBT.md` | **yes** | **no** | The human report rendered from `debt.jsonl` by `gotdocs debt render`. Bounded to `debt.max_report_lines` entries per finding kind. |
| `templates/doc.md` | no | yes | Scaffold for `gotdocs new doc <id>`. |
| `templates/runbook.md` | no | yes | Scaffold for `gotdocs new runbook <id>`. |
| `templates/onboarding.md` | no | yes | Scaffold for `gotdocs new onboarding <id>`. |
| `templates/dependency.md` | no | yes | Scaffold for `gotdocs new dependency <id>`. |
| `templates/decision.md` | no | yes | Scaffold for `gotdocs new decision "<title>"`. Carries the two body sections `gotdocs why` quotes. |
| `hooks/pre-commit` | no | yes | Source of truth for the pre-commit hook. `scripts/install-gotdocs.sh` copies it into `.git/hooks/`. Editing `.git/hooks/pre-commit` directly is pointless — it gets overwritten. |
| `hooks/pre-push` | no | yes | Source of truth for the pre-push hook, installed the same way. Checks the whole range the push would publish. |
| `README.md` | no | yes | This file. |

`debt.jsonl` and `DEBT.md` are generated *and committed*, for the same reason `index.json`
is: the ledger is the record of what the team agreed to live with, and it is only useful if
everyone can read it without running anything. They are also in the default `ignore` list, so
regenerating the ledger can never itself make a document stale.

### `index.json` and `INDEX.md` are generated **and committed**

Both are build outputs that are checked into git on purpose:

- Committed so that an agent (or a human, or CI) can read the whole doc map without running
  anything, and so that a stale index shows up as a reviewable diff.
- Regenerated by `bin/gotdocs index`.
- Reproducible: regenerating with no doc changes produces a **byte-identical** file. There are
  no wall-clock timestamps in them — the only provenance field is `generated_at_sha`. If
  running `bin/gotdocs index` twice in a row produces a diff, that is a bug in the CLI.
- **Do not hand-edit either file.** Any manual change is silently discarded on the next
  regeneration, and `gotdocs check` reports "index out of date vs the working tree" until you
  regenerate. Change the frontmatter in the doc itself, then run `bin/gotdocs index`.

### Config quick reference (`config.json`)

| Key | Meaning |
| --- | --- |
| `version` | Config format version. Currently `1`. |
| `roots` | Directories whose Markdown files are gotdocs documents. Every file under a root must have valid frontmatter. |
| `enforce.pre_commit` | `off` \| `warn` \| `error` — what the local pre-commit hook does with findings. |
| `enforce.pre_push` | `off` \| `warn` \| `error` — what the local pre-push hook does with findings. |
| `enforce.ci` | `off` \| `warn` \| `error` — what CI does with findings. |
| `ignore` | Globs for paths that are never treated as code changes: vendored trees, build output, lockfiles, minified bundles, snapshots, generated protobufs, binary assets. Keeping this tight is what stops a `node_modules` churn from marking half the docs stale. |
| `require_coverage` | When `true`, a changed code path matching no doc's `covers` is itself a finding. Off by default; turn it on once coverage is good, not before. |
| `skip_token` | Put this string in a commit message to bypass the check for that commit. Reliably honored by pre-push, which greps `git log --format=%B BASE..HEAD` — every commit being pushed. **Best effort at pre-commit** — git writes the pending message only *after* the hook runs, so the leftover `COMMIT_EDITMSG` is deliberately ignored when it still matches HEAD's message; use `GOTDOCS_SKIP=1 git commit ...` when it must work. **Not honored by the CI `check` job**, which diffs the whole branch and never reads a commit message; use the `gotdocs-skip` pull request label there. The CI `record` job *does* honor it, in the head commit message, so the ledger commit cannot re-trigger the job. |
| `max_summary_chars` | Hard limit on `summary`. Mirrors the schema's `maxLength`. Default `200`. |

### The `debt` block

The doc-debt ledger. Full treatment in [docs/doc-debt.md](../docs/doc-debt.md).

| Key | Default | Meaning |
| --- | --- | --- |
| `debt.enabled` | `true` | `false` makes every `debt record` a no-op that exits 0, without deleting the history already recorded. |
| `debt.ledger` | `.gotdocs/debt.jsonl` | Where the ledger is written. |
| `debt.report` | `.gotdocs/DEBT.md` | Default output of `gotdocs debt render`. |
| `debt.record_kinds` | all six finding kinds | Which `check` finding kinds are eligible for the ledger. `gotdocs debt record --kinds stale,lint` narrows it for one run. |
| `debt.max_report_lines` | `20` | Lines per finding kind in `DEBT.md`; the rest collapse to "... and N more". Must be >= 1. |

### The `publish` block

Static-site export. Full treatment in [docs/publishing.md](../docs/publishing.md).

| Key | Default | Meaning |
| --- | --- | --- |
| `publish.target` | `docusaurus` | Default `--target` for `gotdocs export`. One of `docusaurus`, `mkdocs`, `starlight`, `jekyll`, `hugo`, `github`. |
| `publish.out_dir` | `build/gotdocs-site` | Default `--out`. |
| `publish.url_prefix` | `""` | Site path the export is served under, used when rewriting links. |
| `publish.source_url` | `""` | Base URL for links that point at code rather than at another document. |
| `publish.layout` | `""` | Jekyll `layout:` value. Empty means `page`. |
| `publish.include_drafts` | `false` | Export `status: draft` documents too. |
| `publish.h1_in_body` | `true` | Whether documents are expected to keep a `# Title` in the body. Read by `lint --portability`'s `h1-count` rule; the exporter reconciles the body H1 to each target regardless. |

Unknown keys inside `debt` and `publish` are kept verbatim and merely reported, so a config
written by a newer gotdocs still loads here. A known key with the **wrong type** is a hard
error (exit 2) — a string where a bool belongs would silently change behaviour.

Missing config file means built-in defaults, so `gotdocs install` can bootstrap a repo that
does not have one yet. A missing config is never an error; a malformed one is exit 2.

### Why the schema is not enforced at runtime

The CLI is Python 3.9+ **stdlib only** — it is vendored into target repos, so it cannot depend
on `jsonschema` (or on PyYAML, see below). Frontmatter validation is re-implemented natively in
`tools/gotdocs/frontmatter.py`. `schema.json` is therefore the precise machine-readable
statement of the format, useful for editor integration and third-party tooling, and it is the
reference to check when changing the native validator. **If you change one, change the other in
the same commit.**

## Frontmatter: the supported YAML subset

Every file under a doc root must begin with a frontmatter block delimited by `---` on its own
line, opening on line 1.

```yaml
---
id: gotdocs-cli
title: Gotdocs CLI
type: doc
summary: Stdlib-only CLI that computes which docs a code change impacts.
covers:
  - tools/gotdocs/**
  - bin/gotdocs
owners: ["@mark"]
tags: [cli, tooling]
status: current
updated: 2026-08-14
verified_at: 3d8b6cd
---
```

Required: `id`, `title`, `type`, `summary`, `covers`, `status`, `updated`.
Optional: `owners`, `tags`, `verified_at`, plus **any extra keys**, which are passed through
untouched so a downstream static site generator can add `sidebar_position`, `slug`, `weight`
and friends.

Field rules: `id` is unique repo-wide, matches `^[a-z0-9][a-z0-9-]*$` and is at most 64
characters; `title` is at most 120 characters; `type` is one of `doc` \| `runbook` \|
`onboarding` \| `dependency` \| `decision`; `updated` is a real calendar date as
`YYYY-MM-DD`; `summary` is at most `max_summary_chars` (200) characters; `covers` is a list
of repo-relative glob patterns and may be empty.

`status` is **per type**. Ordinary documents use `current` \| `draft` \| `deprecated`.
Decision records use `proposed` \| `accepted` \| `rejected` \| `superseded` — "current" says
nothing about a decision and "accepted" says nothing about a doc, so the two enums are
disjoint and `lint` picks the right one from `type`.

Decision records also take `symptoms`, `supersedes`, `superseded_by` and `decided_on`, and
their filename must be `NNNN-slug.md` with `id` equal to the stem. See
[docs/decisions.md](../docs/decisions.md).

### Why the subset is restricted

gotdocs ships with **zero third-party dependencies** — no PyYAML — because the CLI is vendored
into whatever repo you are enforcing, and a docs tool that requires a `pip install` does not get
adopted. So frontmatter is parsed by a small stdlib parser, and it supports exactly the four
constructs below. Anything outside them is a **lint error with a file:line message**, never a
silent misparse: gotdocs will tell you what it cannot read rather than quietly guessing wrong
about which code a doc covers.

The subset is not a hardship. Frontmatter is a flat record of metadata; if you need structure
richer than a list of strings, that content belongs in the body of the document.

### Supported constructs

1. `key: scalar` — unquoted, `'single'`-quoted or `"double"`-quoted. Surrounding quotes are stripped.
2. `key: [a, b, c]` — inline flow list of scalars.
3. `key:` followed by indented `- item` lines — block list of scalars.
4. `# comment` lines and blank lines, which are ignored. A `#` inside a quoted scalar is *not* a comment.

### Good and bad, side by side

| | Example | Verdict |
| --- | --- | --- |
| Plain scalar | `title: Gotdocs CLI` | Good |
| Quoted scalar | `title: "Runbook: DB failover"` | Good — quote when the value contains `: ` or starts with `[`, `{`, `#`, `-`, `&`, `*`, `!`, `%`, `@` |
| Unquoted scalar with a colon | `title: Runbook: DB failover` | **Bad** — ambiguous; parsed as key `title` with a value that trips the linter. Quote it. |
| Inline list | `tags: [cli, tooling]` | Good |
| Inline list, quoted items | `owners: ["@mark", "@acme/platform"]` | Good — `@` must be quoted |
| Block list | `covers:` then two-space-indented `  - tools/gotdocs/**` | Good |
| Empty list | `covers: []` | Good |
| Nested map | `meta:` then `  owner: mark` | **Bad** — nested maps unsupported. Flatten to `meta_owner: mark`. |
| Inline map | `meta: {owner: mark}` | **Bad** — flow mappings unsupported. Flatten it. |
| List of maps | `- name: mark` under `owners:` | **Bad** — block list items must be scalars. Use `owners: ["@mark"]`. |
| Multiline literal | `summary: \|` then an indented paragraph | **Bad** — multiline scalars unsupported. `summary` is one sentence; make it one line. |
| Folded scalar | `summary: >` then indented text | **Bad** — same reason. |
| Anchor / alias | `owners: &team ["@mark"]` / `owners: *team` | **Bad** — anchors, aliases and merge keys unsupported. |
| Tag | `updated: !!str 2026-08-14` | **Bad** — explicit tags unsupported. |
| Comment line | `# reviewed 2026-08-14` | Good — preserved on rewrite |
| Trailing comment | `status: current # for now` | **Bad** — treated as part of the scalar. Put the comment on its own line. |
| `#` inside quotes | `title: "Release #42"` | Good — not treated as a comment |
| Date quoted or not | `updated: 2026-08-14` or `updated: "2026-08-14"` | Good — both parse to the same string |
| Non-ISO date | `updated: Aug 14, 2026` | **Bad** — must be `YYYY-MM-DD` |
| Uppercase id | `id: Gotdocs-CLI` | **Bad** — must match `^[a-z0-9][a-z0-9-]*$` |
| Underscored id | `id: gotdocs_cli` | **Bad** — kebab-case only |
| Missing `covers` | key absent entirely | **Bad** — required; use `covers: []` if the doc covers no code |

### Round-trip safety

Into a document that already exists, gotdocs only ever writes two frontmatter fields —
`updated` and `verified_at`, via `bin/gotdocs verify`. (`bin/gotdocs new` fills a whole
scaffold, but that file is brand new and nothing has read it yet.) `verify` rewrites those
two lines in place and preserves every other line,
including ordering, comments and whitespace, byte-for-byte. If a key is absent it is appended at
the end of the frontmatter block. Your formatting, your comments and your SSG keys survive.

## Everyday commands

```sh
bin/gotdocs status                  # what gotdocs thinks of this repo right now
bin/gotdocs index                   # regenerate index.json + INDEX.md (commit the result)
bin/gotdocs lint                    # validate frontmatter across all roots
bin/gotdocs lint --portability      # will these files render on every supported SSG?
bin/gotdocs check --staged          # what the pre-commit hook runs
bin/gotdocs impacted path/to/file   # which docs claim to cover this path
bin/gotdocs verify <doc-id>         # "I read it, it is still accurate" — stamps updated + verified_at
bin/gotdocs new runbook <id>        # scaffold from templates/runbook.md
bin/gotdocs why "what you observed"  # is this an intentional decision, or a bug?
bin/gotdocs debt list               # what did we agree to live with?
bin/gotdocs export --target hugo --out build/site
```

To have Claude do the writing, ask for `/gotdocs-update`.
